## 对现有方案的评估

整体路线是合理的：先隔离网络与抓包，再判断是否存在本地视频接口；如果可以直接局域网取流，则优先走服务器接管；只有在必要时才进入串口、固件备份、固件分析和最小固件修改。

这个顺序有两个优点：

1. 优先选择低风险路径，避免过早刷机或改固件。
2. 在修改固件前要求完整备份、重复校验和恢复验证，能降低变砖风险。

需要注意的是，P3、P4、P5 属于高风险阶段。特别是 UART 接线、SPI Flash 读写、固件 repack 和写回，都必须建立在确认电压、确认接线、完成原始固件多份备份和验证恢复能力之后。

| 尚未备份 SPI Flash | 不应进行任何写入式固件修改 |

## 建议的下一步顺序

### 第一优先级：完成 P0

1. P0-02：建立隔离网络，确保摄像头只连接测试网络，不进入家庭主网。
2. P0-03：安装并验证 Wireshark、Npcap、nmap、VLC、ffmpeg/ffprobe。
3. P0-05：记录摄像头 MAC、IP、启动时间、App 配网和预览行为。
4. P0-06：保存不同场景下的 pcapng 文件。

### 第二优先级：先做网络侧低风险验证

完成 P0 后，优先执行 P1 和 P2：

1. 抓取摄像头上电启动流量。
2. 分析 DNS、TCP、UDP、App 预览和 PTZ 控制流量。
3. nmap 扫描开放端口。
4. 测试 RTSP、ONVIF、HTTP/MJPEG 或私有流地址。
5. 判断是否无需刷机即可取流。

如果能稳定获得本地视频流，应优先进入 P6 服务器侧接管，而不是立即修改固件。

### 第三优先级：只读 UART

只有在网络侧无法满足目标，或需要确认系统内部信息时，再进入 P3。P3 初期应保持只读：

1. 断电确认 GND。
2. 测 RX/TX 空闲电平，确认 3.3 V TTL。
3. 只连接摄像头 TX 到 USB-TTL RX。
4. 保存完整 boot log。

在没有确认电压和只读日志前，不建议连接 USB-TTL TX 到摄像头 RX。

### 第四优先级：固件备份先于任何修改

P4 必须在 P5 之前完成。进入固件修改前至少需要满足：

1. 明确 SPI Flash 型号、容量、电压和引脚。
2. 成功读取完整 Flash 镜像。
3. 连续读取 2-3 次并校验 hash 完全一致。
4. 原始固件至少保留 2-3 份。
5. 验证原始镜像可写回并能正常启动。

未满足这些条件前，不应执行 P5 的写入式修改。
